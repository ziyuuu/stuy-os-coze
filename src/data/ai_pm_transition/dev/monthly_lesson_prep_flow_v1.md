# 月备课派生流程 v1 草案

本流程用于从已批准的 `current_month_plan.md` 派生月度备课材料。

月备课可以自动生成，但只负责把本月要用到的知识、资源和检查入口整理清楚，为后续周备课和日备课提供导航。月备课不回答“本月是否应该做什么”，也不承担周/日层面的细节展开。月备课要做全面深度检索，但不要求通读每份资源正文。

## 1. 输入

必读：

- `mvp_memory/ai_pm_transition/current_month_plan.md`
- `mvp_memory/ai_pm_transition/methodologies/methodology_index.md`
- `mvp_memory/ai_pm_transition/templates/monthly_lesson_prep_template.md`

条件读取：

- 月计划中确认使用的资源材料。
- 相关脚手架、检查表或方法论文件。
- 最近复盘中已经明确的学习困难或能力缺口。

## 2. 月计划与月备课分工

月计划回答：

- 本月做什么。
- 为什么做。
- 做到什么程度。
- 纳入哪些模块。
- 排除或延后哪些模块。
- 预期产出什么证据。
- 周级节奏如何安排。

月备课回答：

- 本月需要先整理什么。
- 资源在哪里。
- 哪些内容已经足以支撑周 / 日备课。
- 哪些内容还需要继续收集。
- 概念顺序是什么。
- 易混点是什么。
- 需要哪些脚手架。
- 哪些入口应留给周 / 日备课继续展开。

## 3. 派生规则

月备课只能围绕月计划中已确认的模块生成。

月备课必须包含知识整理和资源导航结果，否则不得视为有效备课。资源导航的目标不是把每个资源讲到很深，而是把本月需要用到的信息通过全面检索整理到足以支撑后续周 / 日备课的程度。

每个模块的备课应包含：

- 关联月计划模块。
- 知识整理。
- 资源导航结果。
- 概念重点。
- 概念关系。
- 可能混淆点。
- 教学顺序。
- 练习设计入口。
- 检查问题。
- 质量标准。
- 脚手架和反例。
- 哪些内容留给周 / 日备课展开。

## 4. 资源导航卡

每个进入月备课的资源都应生成一张资源导航卡：

```text
Resource ID：
资源名称：
可用材料：
导航状态：已整理清楚 / 可支撑周备课 / 仅定位 / 待用户提供
本月使用范围：
核心概念：
内容范围：
适用边界：
常见误区：
周 / 日备课入口：
可继续收集的内容：
不能声称或不能使用的内容：
```

导航卡要回答：

- 这份资源解决本月什么信息缺口。
- 这份资源现在已经整理到什么程度。
- 后续周 / 日备课从哪里继续接。
- 哪些内容目前还不能被 Codex 直接声称理解完整。

## 5. 输出结构

备课材料必须保存到专门的备课目录 `mvp_memory/ai_pm_transition/lesson_prep_notes/`。月备课推荐按模块保存，而不是按日期保存。

所有月备课文件必须使用 `templates/monthly_lesson_prep_template.md` 的字段结构。月备课可以按模块拆分，但每个模块文件仍应保持该模板的核心字段，不得另起一套结构。

推荐路径：

```text
mvp_memory/ai_pm_transition/lesson_prep_notes/YYYY/month_lesson_prep_YYYY_MM/
├── README.md
├── module_01.md
├── module_02.md
└── module_03.md
```

目录边界：

- `lesson_prep_notes/` 只保存备课材料。
- 月备课、周备课、日备课都应在该目录下建立各自子目录。
- 月备课不得保存到 `monthly_plans/`、`monthly_reviews/`、`weekly_plans/` 或 `daily_plans/`。
- 计划文件只引用备课路径，不复制备课正文。

`README.md` 应包含：

- 备课元信息。
- 备课定位。
- 本月知识地图。
- 资源导航总览。
- 模块清单。
- 强弱周期与备课密度说明。
- 下级备课入口。
- 不得突破的边界。

每个 `module_XX.md` 应包含：

- 备课元信息。
- 备课定位。
- 知识地图。
- 资源导航。
- 教学顺序。
- 练习与脚手架。
- 检查问题。
- 下级备课入口。
- 边界。

## 6. 模块备课生成规则

每个模块备课必须回答：

1. 这个模块服务哪个月目标？
2. 它在完整任务主线中的作用是什么？
3. 本模块涉及哪些知识域和核心概念？
4. 这些概念之间是什么关系？
5. 用户需要先理解哪些概念？
6. 哪些概念容易混淆？
7. 哪些资源已经被整理到足以支撑周 / 日备课？
8. 本模块要保留哪些内容给周 / 日备课继续展开？
9. 本模块要做什么练习入口？
10. 练习产出如何判断质量？
11. 需要哪些脚手架？
12. 哪些内容本模块明确不做？

模块备课不得：

- 新增月计划没有确认的模块。
- 新增月目标。
- 改变产出数量。
- 改变月计划强度。
- 把资源整理量写成目标。
- 把备课内容写成用户已经完成。

## 7. 资源处理规则

月备课必须继承月计划中的资源表。

对每个资源，备课应说明：

- Resource ID。
- 资源名称。
- 使用模块。
- 使用方式：回查 / 阅读 / 案例参考 / 检查标准 / 模板输入 / 周日备课入口。
- 使用范围：哪些部分需要看，哪些部分先不看。
- 预期服务的练习或证据，以及后续会接到哪一周 / 哪一日。
- 使用边界。

如果资源在月计划中标记为“需要复核后才能使用”，月备课不得直接展开该资源内容，只能列为待复核输入。

如果用户已在月计划确认中批准使用某资源，月备课仍应保留该资源的使用边界，不得把它升级为完整课程任务。

## 8. 强弱周期与备课密度

月备课应根据月计划中的周期节奏映射调整密度。

规则：

- 弱周期：减少新概念，增加回顾、整理、资源定位和周 / 日备课入口。
- 强周期：安排主要练习入口、产出推进和较完整的任务拆解。
- 正常周期：用于收敛、补缺、整合和复盘准备。
- 如果月计划使用非自然周周期，月备课必须沿用月计划的周期段，不得强行改成 Week 1-4。

月备课不派生日计划。具体日安排应由后续日计划流程处理。

## 9. 与周计划的关系

月备课先于周计划生成，用于帮助后续周计划和周备课保持教学一致性。

周计划仍必须从 `current_month_plan.md` 和 `current_status.md` 派生。月备课只提供教学、练习和检查支持，不替代周计划。

推荐关系：

```text
current_month_plan.md
→ 月备课
→ current_week_plan.md
→ 周备课
→ daily_plan
→ 日备课
```

## 10. 状态与归档规则

月备课生成后：

- 可以保存到 `lesson_prep_notes/YYYY/month_lesson_prep_YYYY_MM/`。
- 不更新 `current_status.md`。
- 不更新 `current_stage.md`。
- 不修改 `current_month_plan.md`。
- 不保存 `initial.md` / `final.md` 双快照。

如果月计划在月内经用户批准发生模块或目标调整，应重新检查受影响的月备课模块，并按需更新或补充对应模块备课。

## 11. 禁止事项

月备课不得：

- 替代月计划。
- 替代周计划或日计划。
- 新增月目标、模块或核心产出。
- 记录完成事实。
- 评价用户产出。
- 更新当前状态。
- 修改阶段计划。
- 修改 `master_plan.md` 或 `annual_plan.md`。
- 把课程、书籍或资源写成已完成学习事实。
- 把未复核资源写成已批准必学任务。
