# 月备课派生流程

本流程用于从已确认的 `current_month_plan.md` 派生月度备课材料。

月备课可以自动生成，但只能展开已确认的月计划内容。月备课回答“本月需要先整理什么、资源在哪里、后续周/日备课如何接上”，不回答“本月是否应该做什么”。月备课要求**全面深度检索**，但不要求通读每份资源正文。

## 1. 启动前提

启动月备课前必须满足：

- `current_month_plan.md` 已按正式月计划模板生成。
- 月计划已经用户确认。
- 月初快照 `monthly_plans/YYYY/month_plan_YYYY_MM/initial.md` 已保存。
- `current_status.md` 和 `current_stage.md` 已按月计划生成流程更新。

如果月计划仍是模拟稿、候选草案或未确认版本，不得生成正式月备课，只能生成备课候选说明。

## 2. 读取顺序与输入

必读文件按以下顺序读取：

- `mvp_memory/ai_pm_transition/current_month_plan.md`
- `mvp_memory/ai_pm_transition/templates/month_plan_template.md`
- `mvp_memory/ai_pm_transition/methodologies/methodology_index.md`
- `mvp_memory/ai_pm_transition/templates/monthly_lesson_prep_template.md`
- `mvp_memory/ai_pm_transition/current_status.md`
- `mvp_memory/ai_pm_transition/current_stage.md`

存在时必读：

- 月计划中确认使用的资源原文、索引或复核记录。
- 月计划中列出的脚手架、检查表、模板或方法论文件。
- 最近一次已确认月复盘、周复盘或日复盘中与学习困难、能力缺口、资源使用有关的事实。
- 用户本轮明确提供的现实约束或备课偏好。

说明：

- 如果资源材料不存在，应在备课中标记为“资源待补充 / 待定位”，不得编造资源内容。
- 如果复盘记录不存在，应说明缺少复盘输入，不得假设用户已暴露某个困难。

## 3. 月计划字段到月备课的映射

月备课必须基于正式月计划模板逐项派生。

| 月计划字段 | 月备课使用方式 | 不得做什么 |
| --- | --- | --- |
| 月份与状态 | 确认备课周期、阶段和保存路径 | 不改变月计划状态 |
| 来源文件与生成依据 | 保留上级边界和用户确认事项 | 不重新解释为新计划 |
| 本月定位 | 提炼本月教学重心和备课原则 | 不泛化成课程目录 |
| 本月目标 | 将目标拆成概念、练习、检查标准 | 不新增目标 |
| 本月学习模块 | 每个纳入模块生成备课单元 | 不新增未确认模块 |
| 完整任务主线 | 决定教学顺序和任务衔接 | 不把任务拆成孤立知识点 |
| 资源与课程支撑线 | 为每个模块标明资源调用方式和边界 | 不把资源写成必学清单 |
| 练习、脚手架与产出 | 设计练习步骤、示例、反例和质量标准 | 不记录完成事实 |
| 周期节奏映射 | 决定备课密度、强弱段和认知负荷 | 不派生日计划 |
| 现实约束与强度 | 调整讲解深度、练习数量和脚手架强度 | 不替用户假设时间精力 |
| 月备课派生说明 | 作为备课范围的直接约束 | 不突破该字段边界 |
| 月复盘重点 | 设计检查问题和观察点 | 不提前写复盘结论 |
| 调整规则与边界 | 保留不得做事项和需批准事项 | 不绕过用户批准 |

## 4. Codex 备课判断

生成月备课前，Codex 必须先对月计划做一次备课判断。

备课判断应包含：

- 知识整理：本月需要讲清的知识域、核心概念、概念关系和先后依赖。
- 资源整理与导航：从月计划确认资源、资源索引、方法论文件和可用历史材料中做全面检索，整理出本月需要知道什么、资源在哪里、哪些内容能支撑周/日备课、哪些内容还要继续收集。
- 本月教学重心：本月真正需要讲清、练熟、检查的内容。
- 模块顺序：哪些模块应先讲，哪些模块依赖前置理解，哪些只需月内定位即可。
- 概念负荷：哪些模块概念密度高，哪些模块适合轻处理。
- 练习负荷：哪些模块需要产出，哪些模块只需理解或检查。
- 脚手架强度：哪些模块需要示例、反例、检查表或模板，哪些脚手架应留给周/日备课展开。
- 资源调用：每个资源服务哪个模块、如何调用、使用边界是什么，哪些资源只是导航入口。
- 检查设计：哪些问题用于检查理解，哪些问题用于检查产出质量。
- 风险点：哪些地方容易把计划目标误写成完成事实，或把月备课写重、挤占周/日备课空间。

如果发现月计划字段缺失、目标与证据不匹配、资源引用不完整、资源内容不可获取、资源尚未整理清楚或模块边界不清，Codex 应先输出“备课阻塞 / 待确认事项”，不得直接补造内容。

## 5. 知识整理与资源导航

月备课必须包含知识整理和资源导航结果，否则不得视为有效备课。

知识整理至少包含：

- 本月知识地图：本月涉及的知识域和概念关系。
- 核心概念清单：每个概念的工作定义和用途。
- 概念依赖顺序：哪些概念必须先理解，哪些可以后置。
- 常见混淆：容易混淆的概念对、错误理解和反例。
- 应用场景：每个概念如何服务本月完整任务主线，以及它会在周/日备课中如何继续展开。

资源导航至少包含：

- 资源导航摘要：这份资源能帮助解决本月哪个学习问题。
- 内容范围：资源当前已经定位到哪些章节、笔记或段落。
- 核心概念：资源里最值得继续保留的概念、框架或判断标准。
- 周 / 日备课入口：这份资源后续最适合接到哪一周、哪一日的备课。
- 常见误区：哪些地方容易误解、误用或过度泛化。
- 还需收集的内容：哪些信息还不够，后续周/日备课前要继续补。
- 与月计划映射：资源内容服务哪个目标、模块、完整任务节点和预期证据。
- 使用边界：哪些内容只做导航，哪些内容不进入本月，哪些内容不能写成完成事实。

资源导航输出应区分：

- 已整理清楚、可直接作为周/日备课入口的内容。
- 只完成定位、还不能直接展开的内容。
- 待复核或待定位的内容。
- 不应进入本月备课的内容。

资源导航深度规则：

- 仅阅读 `resource_catalog.md` 的资源摘要，不足以视为完成资源导航。
- 月备课阶段不要求通读资源正文；应优先通过目录、索引、摘要、标签、链接、历史复盘和用户标注做全面检索。
- 如果某些资源的正文阅读会阻塞周 / 日备课，再把阅读动作留给后续周 / 日备课。
- 如果资源原文或用户笔记不可用，Codex 不得伪造资源内容；只能生成“资源待补充导航框架”，并明确列出需要用户提供或后续复核的材料。
- 对版权或付费课程内容，只能使用用户合法提供的笔记、摘要、短引用或可公开访问的材料；不得复制或重构受版权保护的课程全文。
- 当资源内容尚未整理清楚时，月备课应降级为“备课准备清单”，不能假装 Codex 已经完成资源导航。

每个进入月备课的资源都应生成一张资源导航卡：

```text
Resource ID：
资源名称：
可用材料：
导航状态：已整理清楚 / 可支撑周备课 / 仅定位 / 待用户提供
本月使用范围：
核心概念：
内容范围：
适用边界：
常见误区：
周 / 日备课入口：
可继续收集的内容：
不能声称或不能使用的内容：
```

## 6. 输出结构

备课材料必须保存到专门的备课目录 `mvp_memory/ai_pm_transition/lesson_prep_notes/`。月备课推荐按模块保存，而不是按日期保存。

所有月备课文件必须使用 `templates/monthly_lesson_prep_template.md` 的字段结构。月备课可以按模块拆分，但每个模块文件仍应保持该模板的核心字段，不得另起一套结构。

推荐路径：

```text
mvp_memory/ai_pm_transition/lesson_prep_notes/YYYY/month_lesson_prep_YYYY_MM/
├── README.md
├── module_01.md
├── module_02.md
└── module_03.md
```

目录边界：

- `lesson_prep_notes/` 只保存备课材料。
- 月备课、周备课、日备课都应在该目录下建立各自子目录。
- 月备课不得保存到 `monthly_plans/`、`monthly_reviews/`、`weekly_plans/` 或 `daily_plans/`。
- 计划文件只引用备课路径，不复制备课正文。

`README.md` 应包含：

- 备课元信息。
- 备课定位。
- 本月知识地图。
- 资源导航总览。
- 模块清单。
- 强弱周期与备课密度说明。
- 下级备课入口。
- 不得突破的边界。

每个 `module_XX.md` 应包含：

- 备课元信息。
- 备课定位。
- 知识地图。
- 资源导航。
- 教学顺序。
- 练习与脚手架。
- 检查问题。
- 下级备课入口。
- 边界。

## 7. 模块备课生成规则

每个模块备课必须回答：

1. 这个模块服务哪个月目标？
2. 它在完整任务主线中的作用是什么？
3. 本模块涉及哪些知识域和核心概念？
4. 这些概念之间是什么关系？
5. 用户需要先理解哪些概念？
6. 哪些概念容易混淆？
7. 哪些资源已经被整理到足以支撑周 / 日备课？
8. 本模块要做什么练习？
9. 练习产出如何判断质量？
10. 需要哪些脚手架？
11. 哪些资源需要调用，调用到什么程度？
12. 哪些内容本模块明确不做？

模块备课不得：

- 新增月计划没有确认的模块。
- 新增月目标。
- 改变产出数量。
- 改变月计划强度。
- 把资源学习量写成目标。
- 把备课内容写成用户已经完成。

## 8. 资源处理规则

月备课必须继承月计划中的资源表。

对每个资源，备课应说明：

- Resource ID。
- 资源名称。
- 使用模块。
- 使用方式：回查 / 阅读 / 案例参考 / 检查标准 / 模板输入 / 周日备课入口。
- 使用范围：哪些部分需要看，哪些部分先不看。
- 预期服务的练习或证据，以及后续会接到哪一周 / 哪一日。
- 使用边界。

如果资源在月计划中标记为“需要复核后才能使用”，月备课不得直接展开该资源内容，只能列为待复核输入。

如果用户已在月计划确认中批准使用某资源，月备课仍应保留该资源的使用边界，不得把它升级为完整课程任务。

## 9. 强弱周期与备课密度

月备课应根据月计划中的周期节奏映射调整密度。

规则：

- 弱周期：减少新概念，增加回顾、整理、示例和检查问题。
- 强周期：安排主要练习、产出推进和较完整的任务拆解。
- 正常周期：用于收敛、补缺、整合和复盘准备。
- 如果月计划使用非自然周周期，月备课必须沿用月计划的周期段，不得强行改成 Week 1-4。

月备课不派生日计划。具体日安排应由后续日计划流程处理。

## 10. 与周计划的关系

推荐关系：

```text
current_month_plan.md
→ 月备课
→ current_week_plan.md
→ 周备课
→ daily_plan
→ 日备课
```

月备课可以先于周计划生成，用于帮助后续周计划和周备课保持教学一致性。

周计划仍必须从 `current_month_plan.md` 和 `current_status.md` 派生。月备课只提供教学、练习和检查支持，不替代周计划。

## 11. 状态与归档规则

月备课生成后：

- 可以保存到 `lesson_prep_notes/YYYY/month_lesson_prep_YYYY_MM/`。
- 不更新 `current_status.md`。
- 不更新 `current_stage.md`。
- 不修改 `current_month_plan.md`。
- 不保存 `initial.md` / `final.md` 双快照。

如果月计划在月内经用户批准发生模块或目标调整，应重新检查受影响的月备课模块，并按需更新或补充对应模块备课。

## 12. 禁止事项

月备课不得：

- 替代月计划。
- 替代周计划或日计划。
- 新增月目标、模块或核心产出。
- 记录完成事实。
- 评价用户产出。
- 更新当前状态。
- 修改阶段计划。
- 修改 `master_plan.md` 或 `annual_plan.md`。
- 把课程、书籍或资源写成已完成学习事实。
- 把未复核资源写成已批准必学任务。
