# 周计划生成流程

本流程用于从已确认的月计划派生可执行的周计划。

周计划是月计划的下级计划，不是新的战略计划。周计划回答“本周期做什么、产出什么、如何为日计划留下入口”，不得新增月目标、突破阶段边界或把计划内容写成完成事实。

## 1. 触发条件

周计划必须由用户明确触发。

允许触发表达包括：

- 周计划
- 制定本周计划
- 生成下一周计划
- 从当前月计划派生周计划

不得自动触发：

- 不因日期进入新周而自动生成。
- 不因月计划已确认而自动生成。
- 不因存在月备课而自动生成。

## 2. 前置状态检查

生成周计划前必须检查：

- `current_status.md` 是否允许基于已确认月计划派生周计划。
- `current_month_plan.md` 是否为正式已确认月计划。
- `current_stage.md` 是否与当前月计划一致。
- 当前是否已有 `current_week_plan.md` 或已归档周计划。
- 是否存在最近一次已确认周复盘或月复盘，可作为调整输入。

如果月计划未确认、状态文件不允许派生周计划，或上级文件之间存在冲突，不得生成正式周计划，只能输出阻塞说明或候选方案。

## 3. 读取顺序与输入

必读文件按以下顺序读取：

- `mvp_memory/ai_pm_transition/current_status.md`
- `mvp_memory/ai_pm_transition/current_stage.md`
- `mvp_memory/ai_pm_transition/current_month_plan.md`
- `mvp_memory/ai_pm_transition/templates/week_plan_template.md`
- `mvp_memory/ai_pm_transition/methodologies/methodology_index.md`

存在时必读：

- 当前月备课目录：`mvp_memory/ai_pm_transition/lesson_prep_notes/YYYY/month_lesson_prep_YYYY_MM/`
- 最近一次已确认周复盘：`mvp_memory/ai_pm_transition/weekly_reviews/`
- 最近一次已确认月复盘：`mvp_memory/ai_pm_transition/monthly_reviews/`
- 当前用户明确提供的现实约束、时间约束或节奏偏好

月备课只提供教学、练习和检查支持，不替代周计划。周计划仍必须以 `current_month_plan.md` 和 `current_status.md` 为直接上游。

## 4. 周期粒度规则

周计划以月计划阶段为核心粒度，而不是机械按自然周切分。

规则：

- 如果月计划阶段少于 7 天，仍可按该阶段生成一个周计划。
- 如果月计划阶段跨自然周，应优先保持阶段目标完整。
- 如果用户明确要求自然周计划，可以在不破坏月计划阶段目标的前提下切分。
- 如果一个周期内横跨两个阶段，必须说明每个阶段的任务边界和产出边界。
- 弱阶段降低新概念和产出密度，偏启动、整理、补缺、检查和收敛。
- 强阶段提高练习和产出密度，但不得把所有月目标压入单周。

## 5. 生成判断

生成周计划前，Codex 必须先做一次周计划判断：

- 本周期对应月计划的哪个阶段。
- 本周期服务哪些月目标和学习模块。
- 本周期应形成哪些证据。
- 本周期调用哪些资源，调用到什么程度。
- 本周期需要哪些脚手架和检查标准。
- 本周期是否需要降密度或拆分。
- 最近复盘事实是否要求调整任务、资源或脚手架。
- 哪些事项需要用户确认后才能进入周计划。

不得把月计划目标、月备课内容、历史资产存在或计划中的产出写成已完成事实。

## 6. 输出结构

周计划必须使用 `templates/week_plan_template.md` 的字段结构。

周计划至少包含：

- 周期。
- 来源月计划。
- 对应月计划阶段。
- 本周目标。
- 本周学习重点。
- 本周练习。
- 本周产出。
- 日计划拆分入口。
- 周备课入口。
- 周复盘问题。
- 边界。

每个本周目标必须能追溯到：

- 月目标。
- 月计划模块。
- 预期证据。
- 检查标准。

## 7. 保存与状态规则

正式周计划可保存到：

```text
mvp_memory/ai_pm_transition/weekly_plans/YYYY/week_plan_YYYY_MM_DD.md
```

并可同步更新：

```text
mvp_memory/ai_pm_transition/current_week_plan.md
```

保存或更新前必须确保：

- 用户已明确要求生成正式周计划。
- 周计划没有新增月目标或突破边界。
- 周计划没有记录完成事实。
- 不修改 `master_plan.md`、`annual_plan.md` 或 `current_month_plan.md`。

## 8. 禁止事项

周计划不得：

- 新增月计划没有确认的目标、模块或核心产出。
- 启动未授权的正式用户访谈、主作品集、复杂 Demo、RAG 或 Agent 实验。
- 把课程、书籍或资源完成量写成目标。
- 把旧资产存在写成当前能力证据。
- 自动派生日计划。
- 自动生成周备课或周复盘。
- 自动修改 `master_plan.md`、`annual_plan.md` 或 `current_month_plan.md`。

## 9. 验证清单

周计划完成前应检查：

- 是否由用户明确触发。
- 是否读取了当前状态、当前阶段和当前月计划。
- 当前月计划是否已确认。
- 周期是否服从月计划阶段节奏。
- 每个目标是否对应月目标、模块、证据和检查标准。
- 是否只把资源作为任务支撑，而不是完成目标。
- 是否没有记录完成事实。
- 是否没有启动未授权事项。
