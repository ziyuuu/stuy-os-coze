# 月计划半自动生成流程

本流程用于生成 `ai_pm_transition/current_month_plan.md`。

月计划生成是半自动流程：Codex 负责读取、综合、提出候选和暴露决策信息；用户负责确认关键取舍。没有用户最终确认，不得生成正式月计划。

## 1. 前置状态检查

生成前必须检查：

- `current_status.md` 是否允许进入月计划生成。
- `current_stage.md` 是否提供可用于月计划生成的阶段输入。
- 当前是完全冻结、只允许模板设计，还是临时开放 Month 1 / Phase 0 月计划生成。
- `current_month_plan.md` 是否已有草案或当前窗口内容。
- 是否存在上月 `final.md` 或对应月复盘可供参考。

如果状态文件显示不允许进入月计划生成，则不得生成正式月计划，只能继续做流程、模板或候选方案设计。当前状态如果是“临时开放 Month 1 / Phase 0 月计划生成”，可以进入本流程，但这不等于阶段已进入实际学习执行。

## 2. 读取顺序与输入

必读文件按以下顺序读取：

- `mvp_memory/ai_pm_transition/current_status.md`
- `mvp_memory/ai_pm_transition/methodologies/methodology_index.md`
- `mvp_memory/ai_pm_transition/templates/month_plan_template.md`
- `mvp_memory/ai_pm_transition/current_stage.md`
- `mvp_memory/ai_pm_transition/annual_plan.md`
- `mvp_memory/ai_pm_transition/master_plan.md`

读取顺序说明：

- 先读 `current_status.md`，判断当前是否允许进入月计划生成，以及是否存在冻结期、迁移期或其他执行限制。
- 再读方法论和模板，明确月计划应如何组织、计划与备课如何分离、当前模板约束是什么。
- 再读 `current_stage.md`，确认月计划的直接上级和当前阶段边界。
- 最后读 `annual_plan.md` 和 `master_plan.md`，用于校验年度框架和长期边界，避免跳过阶段计划直接生成月计划。

存在时必读：

- 上月 `monthly_plans/YYYY/month_plan_YYYY_MM/final.md`
- 上月或最近一次 `monthly_reviews/`
- 资源复核文件
- 当前用户明确指定的补充上下文

说明：

- “存在时必读”表示：如果这些文件或记录已经存在，并且与当前月计划生成相关，就必须读取，不应被视为可忽略的可选输入。
- 如果不存在，应在生成前摘要中说明“未发现对应历史输入”，而不是假设已有历史结论。

月回顾影响规则：

- 上月或最近一次月回顾 / 月复盘是下月计划的重要输入，不只是背景参考。
- 月回顾中的完成事实、未完成事实、能力变化、资源使用情况、计划偏差和下月调整建议，必须进入生成前摘要。
- 月回顾可以影响下月主方向建议、模块纳入 / 延后 / 排除、强度选择、产出密度、风险提示和备课脚手架强度。
- 月回顾不得自动改写 `master_plan.md`、`annual_plan.md` 或 `current_stage.md`。
- 如果月回顾建议改变阶段、年度方向或长期目标，Codex 必须把它作为“需要用户确认的调整建议”暴露出来，不能直接应用。
- 如果没有月回顾，应明确说明缺少该输入，并提高对 `current_status.md` 和用户现实约束确认的依赖。

月计划历史影响规则：

- 上月或最近一次 `final.md` 是下月计划的重要输入，不只是历史快照。
- Codex 必须对历史月计划做一次规划判断，提炼哪些目标、模块、练习、产出、资源、周节奏、边界和备课入口应影响下月。
- 历史月计划中的计划内容不是完成事实，不能因为写在 `final.md` 中就视为已完成。
- 历史月计划可以帮助判断计划结构、承诺范围、未必执行的意图、月内调整轨迹和下月衔接点。
- 历史月计划不得自动成为新月计划模板或直接复制到新月计划。
- 如果历史月计划与月回顾冲突，应优先暴露冲突并请求用户确认；不能用计划内容覆盖回顾事实。

月计划规划判断应至少包含：

- 哪些历史目标仍应作为下月候选承接项。
- 哪些历史目标已经不适合继续承接。
- 哪些模块结构可复用，哪些模块需要重组。
- 哪些练习和产出承诺过密，需要降密度。
- 哪些资源进入过计划但需要复核、替换或停止。
- 哪些周节奏安排暴露出强弱周设计问题。
- 哪些边界规则需要保留到下月。
- 哪些备课入口应继续展开，哪些不应继续。
- 哪些历史计划内容与月回顾事实或当前状态冲突。
- 哪些事项需要用户确认后才能进入新月计划。

Codex 生成的历史月计划待用户确认事项应按类型输出：

- 建议承接：
- 建议重组：
- 建议取消：
- 建议降密度：
- 建议保留边界：
- 需要资源复核：
- 与月回顾冲突：
- 需要用户补充现实信息：

月回顾问答嵌入规则：

- 如果存在月回顾，Codex 不能只在摘要中提到它，必须把月回顾内容纳入三轮问答。
- Codex 应先提取月回顾中的关键项目：完成事实、未完成事实、阻塞、能力变化、资源使用、作品集进展、计划偏差和下月调整建议。
- Codex 必须对月回顾做一次规划判断，生成待用户确认事项，而不是把原始月回顾直接丢给用户判断。
- Codex 必须区分“事实”和“建议”：完成 / 未完成 / 阻塞属于事实输入；下月调整属于建议输入，应用前需要用户确认。
- 用户必须有机会确认、修正或拒绝月回顾中的继承项。
- 月回顾建议不能被默认应用到新月计划；只能作为候选取舍和风险提示进入问答。
- 如果用户指出月回顾过时或不准确，应以用户本轮确认后的修正为准，并在生成前摘要中记录修正点。

月回顾规划判断应至少包含：

- 哪些完成事实可以视为下月不必重复安排的内容。
- 哪些未完成事实应作为下月候选承接项。
- 哪些阻塞应转化为下月风险、边界或降密度条件。
- 哪些能力变化说明可以降低脚手架，哪些能力缺口说明需要增加脚手架。
- 哪些资源使用结果说明应继续、替换、复核或停止使用某些资源。
- 哪些作品集进展可以承接，哪些不应被误写成已完成作品集证据。
- 哪些月回顾中的下月调整建议与 `current_stage.md`、`annual_plan.md` 或 `master_plan.md` 冲突。
- 哪些事项需要用户确认后才能进入新月计划。

Codex 生成的待用户确认事项应按类型输出：

- 建议继承：
- 建议延后：
- 建议取消：
- 建议降密度：
- 建议增加脚手架：
- 需要资源复核：
- 可能冲突：
- 需要用户补充现实信息：

## 3. 决策信息卡规则

每个关键问题前，Codex 必须先暴露决策信息，而不是只问用户确认。

格式：

```text
决策点：
- 这一步需要用户决定什么。

已知依据：
- 来自哪些文件。
- 哪些事实或约束影响判断。

Codex 当前判断：
- 推荐选项是什么。
- 为什么推荐。

可选方案：
- A：
- B：
- C：

选择影响：
- 选 A 会影响什么。
- 选 B 会影响什么。
- 哪些风险会增加或降低。

不确定信息：
- Codex 还不知道什么。
- 哪些真实情况需要用户补充。

请用户确认：
- 本轮最小需要回答的问题。
```

## 4. 三轮问答流程

### 第 1 轮：状态与阶段闸门

Codex 输出：

- 当前阶段。
- 阶段状态：冻结 / 临时开放 Month 1 / Phase 0 月计划生成 / 月计划待确认 / 月计划已确认 / 实际学习执行中。
- 当前月计划是否允许生成。
- `current_status.md` 中的关键约束。
- 上月或最近一次历史月计划摘要，如果存在：
  - 原计划目标。
  - 原计划模块。
  - 原计划产出。
  - 原计划周节奏。
  - 原计划边界。
- Codex 对历史月计划的规划判断，如果存在：
  - 建议承接。
  - 建议重组。
  - 建议取消。
  - 建议降密度。
  - 建议保留边界。
  - 与月回顾或当前状态的冲突。
- 上月或最近一次月回顾摘要，如果存在：
  - 完成事实。
  - 未完成事实。
  - 主要阻塞。
  - 能力变化。
  - 下月调整建议。
- Codex 对月回顾的规划判断，如果存在：
  - 建议继承。
  - 建议延后。
  - 建议取消。
  - 建议降密度或增加脚手架。
  - 可能冲突。
  - 需要用户确认的事项。
- 当前生成行为属于月计划生成、修订、归档，还是模板演练。
- 发现的冲突。

用户至少确认：

- 本月是否沿用当前阶段。
- 是否允许进入月计划生成流程。
- Codex 对历史月计划的规划判断中，哪些判断接受、修正或拒绝。
- 月回顾摘要是否准确，哪些内容需要修正或不应继承。
- Codex 对月回顾的规划判断中，哪些判断接受、修正或拒绝。

如果状态文件不允许进入月计划生成，或阶段文件不能作为月计划生成输入，或状态文件之间存在冲突，不进入下一轮。不得把“允许生成月计划”误写成“已经进入实际学习执行”。

### 第 2 轮：方向与模块取舍

Codex 输出：

- 候选本月主方向。
- 候选本月定位：
  - 本月在当前阶段中的功能。
  - 本月要为下月或下一阶段澄清的问题。
  - 本月完成后应提供的输入价值。
- 候选本月目标：
  - 每个目标的来源依据。
  - 每个目标服务的阶段目标。
  - 每个目标对应的预期证据。
  - 每个目标的检查标准。
- 候选模块清单。
- 建议纳入的模块。
- 建议放入边界的延后事项。
- 建议放入边界的排除事项。
- 每个模块来源于哪个上级文件。
- 每个模块服务哪个阶段目标。
- 模块之间是否存在前置关系。
- 月回顾如何影响模块取舍，如果存在：
  - 哪些未完成事项建议承接。
  - 哪些已完成事项不应重复安排。
  - 哪些能力缺口建议补强。
  - 哪些下月调整建议可采纳、暂缓或拒绝。
- 历史月计划如何影响模块取舍，如果存在：
  - 哪些原模块建议承接。
  - 哪些原模块建议重组。
  - 哪些原模块建议取消或不重复安排。
  - 哪些原模块与月回顾事实冲突。
- Codex 基于月回顾提出的待确认模块处理建议：
  - 建议纳入的承接模块。
  - 建议延后的模块。
  - 建议取消或不重复安排的模块。
  - 建议增加脚手架的模块。
- Codex 基于历史月计划提出的待确认模块处理建议：
  - 建议承接的模块。
  - 建议重组的模块。
  - 建议取消的模块。
  - 建议降密度的模块。
- 纳入或延后会带来的影响。

用户至少确认：

- 本月定位是否具体、准确。
- 本月主方向。
- 本月目标是否过多、过少或表述过虚。
- 每个目标对应的证据和检查标准是否合理。
- 纳入模块。
- 放入边界的延后事项。
- 放入边界的排除事项。
- 从月回顾继承哪些未完成事项或调整建议。
- 不再继承哪些月回顾内容。
- 是否接受 Codex 基于月回顾提出的模块处理建议。
- 从历史月计划承接、重组或取消哪些目标和模块。
- 是否接受 Codex 基于历史月计划提出的模块处理建议。

### 第 3 轮：现实约束、产出与边界

Codex 输出：

- 年度计划中的强弱周原则。
- 当前状态中的现实限制。
- 月回顾暴露的执行偏差、阻塞、能力缺口或恢复需求，如果存在：
  - 需要降低强度的证据。
  - 需要增加脚手架的证据。
  - 需要减少产出数量的证据。
  - 可以提高强度的证据。
- 历史月计划暴露的计划密度、周节奏和边界问题，如果存在：
  - 目标是否过多。
  - 产出是否过密。
  - 周节奏是否过紧。
  - 边界是否需要保留。
- Codex 基于月回顾提出的待确认强度和风险建议：
  - 建议强度。
  - 建议降密度周。
  - 建议风险边界。
  - 建议备课脚手架。
- Codex 基于历史月计划提出的待确认强度和节奏建议：
  - 建议强度。
  - 建议减少或保留的产出。
  - 建议降密度周。
  - 建议保留的边界。
- 候选产出数量与强度关系。
- 偏弱 / 正常 / 偏强三种强度的影响。
- 资源引用完整性检查：
  - Resource ID。
  - 资源名称。
  - 来源 / URL。
  - 候选状态。
  - 复核建议。
  - 本月使用方式。
  - 服务目标 / 模块。
  - 预期练习或证据。
  - 使用边界。
- 可能需要复核的资源及复核原因。
- 本月不应做的事项。

用户至少确认：

- 本月强度：偏弱 / 正常 / 偏强。
- 哪些周需要降密度。
- 本月必须形成的产出证据。
- 本月明确不做的事项。
- 是否允许某些资源进入月计划。
- 资源引用缺失字段是否需要补齐，或是否允许标记为待补充。
- 月回顾中的阻塞和偏差是否需要转化为本月风险、边界或备课脚手架。
- 是否接受 Codex 基于月回顾提出的强度、风险和脚手架建议。
- 是否接受 Codex 基于历史月计划提出的强度、节奏和边界建议。

## 5. 生成前理解校验规则

在正式生成月计划前，Codex 必须基于已读取文件、历史月计划、月回顾和三轮问答，先输出自己的计划理解，并向用户提出少量关键问题。

这一步不是生成计划正文，而是防止 Codex 带着错误理解进入写作。

Codex 应输出：

- 我对本月计划的当前理解：
  - 本月主方向。
  - 本月定位。
  - 本月目标及其对应证据和检查标准。
  - 应纳入的核心模块。
  - 应放入边界的延后或排除事项。
  - 应承接的历史月计划内容。
  - 应继承的月回顾事项。
  - 本月强度和节奏倾向。
  - 本月主要风险和边界。
- 我准备如何组织月计划：
  - 本月定位如何具体化。
  - 本月目标如何避免空泛，并如何连接证据和检查标准。
  - 完整任务主线如何表达。
  - 资源与练习如何服务任务。
  - 资源引用如何补全来源、状态、复核建议和边界。
  - 产出和检查标准如何设定。
  - 月复盘重点如何反向检查目标、资源、产出和计划偏差。
  - 月备课入口如何保留。
- 我仍不确定的问题：
  - 影响主方向的问题。
  - 影响模块取舍的问题。
  - 影响强度和产出密度的问题。
  - 影响资源使用或复核的问题。
  - 影响资源引用完整性的问题。
  - 影响月复盘重点的问题。
  - 影响边界和风险的问题。

Codex 提问规则：

- 问题必须来自 Codex 对计划的具体理解，不能泛泛问“还有什么补充吗”。
- 每轮只问必要问题，优先 1-3 个。
- 每个问题都要说明为什么影响月计划。
- 如果某个问题不影响月计划结构，不应在此轮提出。
- 用户回答后，Codex 必须更新自己的计划理解，再进入最终确认。

推荐格式：

```text
生成前理解校验

我当前理解：
- ...

我准备这样组织月计划：
- ...

我还有这些关键不确定点：
1. 问题：
   为什么重要：
   影响字段：
2. 问题：
   为什么重要：
   影响字段：

请先回答这些问题。回答后我再给最终确认摘要，不直接生成计划。
```

## 6. 最终确认语

正式生成前，Codex 必须要求用户给出明确确认。

最终确认语只能在“生成前理解校验”完成后给出。

推荐格式：

```text
确认：本月沿用 X 阶段，主方向为 Y，纳入 A/B/C 模块，延后 D，排除 E；从历史月计划承接 H/I，重组 J，取消 K；从月回顾中继承 M/N，暂不继承 P；本月强度为 Z；按以上约束生成 current_month_plan.md。
```

没有最终确认，不得生成正式 `current_month_plan.md`。

## 7. 生成当前月实例

用户确认后，Codex 才能生成或更新：

```text
mvp_memory/ai_pm_transition/current_month_plan.md
```

生成规则：

- 使用正式月计划模板的结构。
- 保持人类可读 Markdown。
- 不写成日计划。
- 不写完成事实。
- 不突破当前阶段边界。
- 不修改 `master_plan.md`。

## 8. 月初快照

`current_month_plan.md` 经用户批准生成后，自动保存月初快照：

```text
mvp_memory/ai_pm_transition/monthly_plans/YYYY/month_plan_YYYY_MM/initial.md
```

规则：

- `initial.md` 是已批准月计划的月初版本。
- 保存 `initial.md` 不需要二次确认，因为它只是保存已批准内容。
- `initial.md` 原则上不回改。

## 9. 状态文件更新

正式月计划经用户确认并保存 `initial.md` 后，必须更新：

- `mvp_memory/ai_pm_transition/current_status.md`
- `mvp_memory/ai_pm_transition/current_stage.md`

更新规则：

- 只记录真实发生的状态变化。
- 可以记录月计划已经确认、月计划周期、月初快照路径、当前阶段已进入可按月计划派生下级计划的状态。
- 可以记录下一步允许事项，例如月备课生成、周计划派生或继续等待用户指令。
- 不得写入学习完成事实。
- 不得写入用户产出、复盘、评价或作品集进展。
- 不得把计划目标写成已完成能力。
- 不得自动修改 `master_plan.md` 或 `annual_plan.md`。

`current_status.md` 应更新工作区当前事实和下一步。

`current_stage.md` 应更新当前阶段与已确认月计划之间的状态关系，确保阶段文件、月计划和状态文件一致。

## 10. 月内调整

`current_month_plan.md` 是当前窗口，月内可以按规则调整。

可调整内容：

- 周节奏映射。
- 资源使用安排。
- 脚手架强度。
- 明确经用户批准的模块范围调整。

必须用户批准的调整：

- 本月主方向变化。
- 纳入 / 排除模块变化。
- 产出证据要求变化。
- 突破或修改阶段边界的变化。

不得写入月计划：

- 完成事实。
- 复盘结论。
- 用户产出评价。
- 对 `master_plan.md` 的自动修改。

## 11. 月末归档

月末切换前，保存当前窗口的最终版本：

```text
mvp_memory/ai_pm_transition/monthly_plans/YYYY/month_plan_YYYY_MM/final.md
```

规则：

- `final.md` 是月末最终计划快照。
- `final.md` 可以反映月内经批准的计划调整。
- `final.md` 不混入月复盘事实。
- 月度完成事实进入 `monthly_reviews/`。

## 12. 历史复用

后续生成新月计划时，可以读取历史：

- 上月 `initial.md`：查看月初承诺。
- 上月 `final.md`：查看月末最终计划状态。
- 上月月复盘：查看完成事实、偏差、能力变化和调整建议。

历史月计划只能作为参考，不能作为模板母本。
