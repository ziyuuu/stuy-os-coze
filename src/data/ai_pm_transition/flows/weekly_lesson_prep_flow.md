# 周备课派生流程

本流程用于从已确认周计划和月备课材料派生周备课。

周备课是 Codex 的自我备课材料，主要读者是后续 Codex 执行线程，而不是用户。周备课用于支持后续日计划、日备课、学习引导、产出检查和复盘判断。

周备课回答“Codex 本周需要先理解什么、如何引导学习、如何设计练习、如何检查产出”，不回答“本周是否应该做什么”。周备课不替代周计划，不记录完成事实，不评价用户产出。

## 1. 启动前提

启动周备课前必须满足：

- `current_month_plan.md` 已确认。
- 当前周计划已生成或用户明确提供了待备课的周计划。
- 周计划没有突破月计划目标和阶段边界。
- 如存在月备课，应优先读取并继承月备课的知识地图、资源导航和模块边界。

如果周计划不存在，不得生成正式周备课，只能输出备课候选说明或提示先生成周计划。

## 2. 读取顺序与输入

必读文件按以下顺序读取：

- `mvp_memory/ai_pm_transition/current_status.md`
- `mvp_memory/ai_pm_transition/current_month_plan.md`
- `mvp_memory/ai_pm_transition/current_week_plan.md`
- `mvp_memory/ai_pm_transition/methodologies/methodology_index.md`
- `mvp_memory/ai_pm_transition/templates/weekly_lesson_prep_template.md`

存在时必读：

- 当前月备课目录：`mvp_memory/ai_pm_transition/lesson_prep_notes/YYYY/month_lesson_prep_YYYY_MM/`
- 周计划中列出的资源、脚手架、检查表或模板
- 最近已确认复盘中与学习困难、能力缺口、资源使用有关的事实
- 用户本轮明确提供的现实约束或备课偏好

如果资源材料不存在，应标记为“资源待补充 / 待定位”，不得编造资源内容。

## 3. AI 自我备课要求

周备课不是面向用户的讲义，而是给后续 AI 线程使用的知识准备记录。

生成周备课前，Codex 必须先完成：

- 资料收集：定位本周周计划、月备课、资源索引、用户合法笔记、旧资产和可用公开资料。
- 必要阅读：阅读足以支撑本周引导、练习和检查的材料；不要求通读所有资源全文。
- 理解整理：把本周知识内容整理成概念、关系、例子、误区、检查标准和边界。
- 自我校准：标记哪些内容已理解可用于引导，哪些只是定位，哪些待补充，哪些不得使用。

理解状态必须使用以下分层：

| 状态 | 含义 | 允许用途 |
| --- | --- | --- |
| 已理解可用于引导 | Codex 已阅读并能解释核心概念、关系、例子和误区 | 可用于日计划、日备课、学习引导和产出检查 |
| 仅定位不可展开 | 只找到资源入口、目录或摘要，尚不足以讲解 | 只能提示后续补读或作为资源入口 |
| 待补充 | 缺少必要材料、正文、笔记或用户授权输入 | 不能生成具体讲解，只能列为待补充 |
| 不得使用 | 版权、权限、阶段边界或资源质量不允许使用 | 不得进入本周讲解、练习或检查标准 |

如果本周关键知识只达到“仅定位不可展开”或“待补充”，周备课必须降级为“备课准备清单”，不得假装 Codex 已具备可引导理解。

## 4. 周计划到周备课的映射

| 周计划字段 | 周备课使用方式 | 不得做什么 |
| --- | --- | --- |
| 周期 | 确认备课范围和节奏 | 不改周计划周期 |
| 来源月计划 | 保留上级目标和边界 | 不新增月目标 |
| 对应月计划阶段 | 决定强弱密度和教学重点 | 不改阶段节奏 |
| 本周目标 | 拆成知识、练习和检查问题 | 不把目标写成已完成 |
| 本周学习重点 | 形成知识地图和教学顺序 | 不扩展为新课程目录 |
| 本周练习 | 设计脚手架、示例和反例 | 不评价用户产出 |
| 本周产出 | 设计质量标准和检查问题 | 不提前写复盘结论 |
| 日计划拆分入口 | 留出日备课入口 | 不自动派生日计划 |
| 周复盘问题 | 设计形成性观察点 | 不提前做复盘 |
| 边界 | 保留禁止事项 | 不绕过用户批准 |

## 5. 教学设计规则

周备课必须采用“完整任务主线 + 课程支撑线 + 程序性脚手架 + 局部专项练习”的结构。

周备课判断应包含：

- 本周完整任务是什么。
- Codex 本周必须先理解哪些知识，为什么这些知识服务周目标。
- 本周需要讲清哪些核心概念。
- 哪些概念应先理解，哪些可以后置。
- 本周资源如何服务任务，哪些资源已经达到可引导理解。
- 本周练习如何产出证据。
- 本周需要哪些模板、步骤、检查表、示例或反例。
- 后续日计划、日备课、学习引导和复盘判断应如何使用本周备课。
- 本周哪些内容适合日备课继续展开。
- 哪些风险容易导致重刷课程、堆资源或突破月计划边界。

Phase 0 默认教学方式：

```text
先回忆 -> 再应用 -> 再查漏 -> 再修正
```

不得把 Phase 0 做成重读书、重刷课或作品集执行。

## 6. 后续线程交接规则

周备课必须让后续 Codex 线程能直接判断：

- 本周知识背景是什么。
- 哪些资源已经读到足以支持引导。
- 哪些核心概念必须反复追问或检查。
- 哪些常见错误需要提前拦截。
- 日计划生成时应如何拆分学习与练习。
- 日备课时应继续阅读或展开哪些材料。
- 学习引导时应优先问什么、避免问什么。
- 周复盘时应观察哪些事实、困难、脚手架效果和资源效果。
- 哪些内容仍不确定，不能被当成已理解内容使用。

周备课不得把 AI 自己的阅读和理解写成用户已经学习或完成。

## 7. 输出结构

周备课必须使用 `templates/weekly_lesson_prep_template.md` 的字段结构。

周备课至少包含：

- 备课元信息。
- 备课定位。
- AI 自我备课摘要。
- 资料收集与理解记录。
- 知识地图。
- 资源导航。
- AI 后续使用说明。
- 教学顺序。
- 练习与脚手架。
- 检查问题。
- 认知负荷控制。
- 日备课入口。
- 周复盘观察点。
- 边界。

## 8. 保存规则

正式周备课推荐保存到：

```text
mvp_memory/ai_pm_transition/lesson_prep_notes/YYYY/weekly_lesson_prep_YYYY_MM_DD.md
```

保存规则：

- 周备课只保存备课材料。
- 不保存到 `weekly_plans/`、`weekly_reviews/` 或 `daily_plans/`。
- 不更新 `current_status.md`。
- 不更新 `current_stage.md`。
- 不修改 `current_month_plan.md` 或 `current_week_plan.md`。

## 9. 禁止事项

周备课不得：

- 替代周计划或日计划。
- 新增月目标、周目标或核心产出。
- 记录完成事实。
- 评价用户产出。
- 更新当前状态。
- 把资源导航写成已完成学习。
- 把未复核资源写成已批准必学任务。
- 把仅定位的资料写成 Codex 已经理解。
- 把 Codex 自己的备课理解写成用户学习完成事实。
- 启动正式访谈、作品集、复杂 Demo、RAG 或 Agent 实验。

## 10. 验证清单

周备课完成前应检查：

- 是否存在已确认或明确指定的周计划。
- 是否继承了月计划和月备课边界。
- 是否明确周备课是 AI 自我备课材料，而不是用户讲义或学习产出。
- 是否完成资料收集、必要阅读和理解整理。
- 是否标注每个关键资源的理解状态。
- 是否区分已理解可用于引导、仅定位不可展开、待补充和不得使用。
- 是否说明后续 Codex 线程如何用于日计划、日备课、学习引导和复盘判断。
- 是否回答了如何引导、如何练、如何检查。
- 是否为日备课留下入口但没有自动派生日计划。
- 是否没有记录完成事实或复盘结论。
- 是否没有更新状态文件。
