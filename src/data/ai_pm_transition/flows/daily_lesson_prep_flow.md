# 日备课派生流程

本流程用于从正式日计划和上级备课材料派生当天备课。

日备课是 Codex 的自我备课材料，主要读者是后续 Codex 执行线程，而不是用户。日备课用于支持当天学习引导、练习推进、产出检查和日复盘判断。

日备课回答“Codex 今天需要先理解什么、如何引导、如何练、如何检查”，不回答“今天是否应该做什么”。日备课不替代日计划，不记录完成事实，不评价用户产出。

## 1. 启动前提

启动日备课前必须满足：

- `current_month_plan.md` 已确认。
- 当前周计划已生成或用户明确提供了待承接的周计划。
- 当前日计划已生成或用户明确提供了待备课的日计划。
- 日计划没有突破周计划、月计划和阶段边界。
- 如存在周备课和月备课，应优先继承其中的知识地图、资源导航、教学顺序、脚手架和边界。

如果日计划不存在，不得生成正式日备课，只能输出备课候选说明或提示先生成日计划。

## 2. 读取顺序与输入

必读文件按以下顺序读取：

- `mvp_memory/ai_pm_transition/current_status.md`
- `mvp_memory/ai_pm_transition/current_month_plan.md`
- `mvp_memory/ai_pm_transition/current_week_plan.md`
- 当天日计划文件或用户明确提供的日计划
- `mvp_memory/ai_pm_transition/methodologies/methodology_index.md`

存在时必读：

- 当前月备课目录：`mvp_memory/ai_pm_transition/lesson_prep_notes/YYYY/month_lesson_prep_YYYY_MM/`
- 当前周备课：`mvp_memory/ai_pm_transition/lesson_prep_notes/YYYY/weekly_lesson_prep_YYYY_MM_DD.md`
- 日计划中列出的资源、脚手架、检查表或模板
- 最近已确认复盘中与学习困难、能力缺口、资源使用有关的事实
- 用户本轮明确提供的现实约束或备课偏好

如果资源材料不存在，应标记为“资源待补充 / 待定位”，不得编造资源内容。

## 3. AI 自我备课要求

日备课不是面向用户的讲义，而是给当天学习运行使用的知识准备记录。

生成日备课前，Codex 必须先完成：

- 资料收集：定位当天日计划、周备课、月备课、资源索引、用户合法笔记、旧资产和可用公开资料。
- 必要阅读：阅读足以支撑当天引导、练习和检查的材料；不要求通读所有资源全文。
- 理解整理：把当天知识内容整理成概念、关系、例子、误区、检查标准和边界。
- 自我校准：标记哪些内容已理解可用于引导，哪些只是定位，哪些待补充，哪些不得使用。

理解状态必须使用以下分层：

| 状态 | 含义 | 允许用途 |
| --- | --- | --- |
| 已理解可用于引导 | Codex 已阅读并能解释核心概念、关系、例子和误区 | 可用于当天学习引导、练习推进和产出检查 |
| 仅定位不可展开 | 只找到资源入口、目录或摘要，尚不足以讲解 | 只能提示后续补读或作为资源入口 |
| 待补充 | 缺少必要材料、正文、笔记或用户授权输入 | 不能生成具体讲解，只能列为待补充 |
| 不得使用 | 版权、权限、阶段边界或资源质量不允许使用 | 不得进入当天讲解、练习或检查标准 |

如果当天关键知识只达到“仅定位不可展开”或“待补充”，日备课必须降级为“备课准备清单”，不得假装 Codex 已具备可引导理解。

## 4. 日计划到日备课的映射

| 日计划字段 | 日备课使用方式 | 不得做什么 |
| --- | --- | --- |
| 日期 | 确认备课范围和当天节奏 | 不改日计划日期 |
| 来源上下文 | 保留上级目标和边界 | 不新增上级目标 |
| 今日目标 | 拆成知识、练习和检查问题 | 不把目标写成已完成 |
| 学习内容 | 形成当天知识地图和教学顺序 | 不扩展为新课程目录 |
| 练习动作 | 设计脚手架、示例和反例 | 不评价用户产出 |
| 观察点 | 转成学习引导和复盘观察入口 | 不提前写复盘结论 |
| 完成标准 | 设计质量标准和自查问题 | 不替代评价 |
| 今日边界 | 保留禁止事项 | 不绕过用户批准 |
| 复盘入口 | 设计事实采集问题 | 不自动生成复盘记录 |

## 5. 教学设计规则

日备课必须采用“当天目标 + 必要概念 + 练习脚手架 + 检查问题 + 复盘观察”的结构。

日备课判断应包含：

- 今天完整任务是什么。
- Codex 今天必须先理解哪些知识，为什么这些知识服务今日目标。
- 今天需要讲清哪些核心概念。
- 哪些概念只需要轻量提示，哪些必须深入检查。
- 今天资源如何服务任务，哪些资源已经达到可引导理解。
- 今天练习如何产出证据。
- 今天需要哪些模板、步骤、检查表、示例或反例。
- 当天学习引导时应优先问什么、避免问什么。
- 当天日复盘时应观察哪些事实、困难、脚手架效果和资源效果。

Phase 0 默认教学方式：

```text
先回忆 -> 再应用 -> 再查漏 -> 再修正
```

不得把 Phase 0 做成重读书、重刷课或作品集执行。

## 6. 输出结构

日备课至少包含：

- 备课元信息。
- 备课定位。
- AI 自我备课摘要。
- 资料收集与理解记录。
- 当天知识地图。
- 资源导航。
- 教学顺序。
- 练习与脚手架。
- 检查问题。
- 认知负荷控制。
- 日复盘观察点。
- 边界。

如未来创建正式日备课模板，应以本结构为最低字段要求。

## 7. 保存规则

正式日备课推荐保存到：

```text
mvp_memory/ai_pm_transition/lesson_prep_notes/YYYY/daily_lesson_prep_YYYY_MM_DD.md
```

保存规则：

- 日备课只保存备课材料。
- 不保存到 `daily_plans/`、`reviews/`、`weekly_plans/` 或 `weekly_reviews/`。
- 不更新 `current_status.md`。
- 不更新 `current_stage.md`。
- 不修改 `current_month_plan.md`、`current_week_plan.md` 或原始日计划。

## 8. 禁止事项

日备课不得：

- 替代日计划。
- 新增月目标、周目标、日目标或核心产出。
- 记录完成事实。
- 评价用户产出。
- 更新当前状态。
- 把资源导航写成已完成学习。
- 把未复核资源写成已批准必学任务。
- 把仅定位的资料写成 Codex 已经理解。
- 把 Codex 自己的备课理解写成用户学习完成事实。
- 启动正式访谈、作品集、复杂 Demo、RAG 或 Agent 实验。

## 9. 验证清单

日备课完成前应检查：

- 是否存在正式或明确指定的日计划。
- 是否继承了周计划、月计划、周备课和月备课边界。
- 是否明确日备课是 AI 自我备课材料，而不是用户讲义或学习产出。
- 是否完成资料收集、必要阅读和理解整理。
- 是否标注每个关键资源的理解状态。
- 是否区分已理解可用于引导、仅定位不可展开、待补充和不得使用。
- 是否回答了如何引导、如何练、如何检查。
- 是否为日复盘留下事实观察入口但没有自动生成复盘。
- 是否没有记录完成事实或复盘结论。
- 是否没有更新状态文件。
