# 方法论索引

本文件承接 `master_plan.md` 中的学习设计细则，用于说明 AI PM 转型学习如何组织任务、课程、脚手架、专项练习、复盘和下级计划。

本文件不是日计划、备课模板或自动路由系统，不记录完成事实，不替代 `master_plan.md`、`annual_plan.md`、`current_stage.md`、`current_month_plan.md` 或 `current_week_plan.md`。

## 1. 核心学习结构

本工作区采用以 4C/ID 思路为主的“完整任务主线 + 连贯课程支撑线 + 程序性脚手架 + 局部专项练习”结构。

完整任务主线负责连接真实或拟真的 C 端 AI 产品问题、目标用户、使用场景、产品假设、AI 介入点、体验路径、eval、反馈和作品集证据。

课程支撑线负责提供产品发现、用户研究、C 端体验、AI 技术、eval、数据边界和求职表达等系统输入。

程序性脚手架负责提供模板、步骤、检查表、反例、质量标准和备课支持。

局部专项练习负责在任务暴露短板时进行短小、及时、可验证的补强。

课程、书籍、官方文档和案例不以“看完”为完成标准，而以能否被应用到产品任务、练习产出和作品集证据中为完成标准。下级计划应避免两种极端：只按课程章节推进导致学完但不会用；只做任务而缺少系统输入，导致经验碎片化、概念不牢和判断失准。

## 2. 完整任务优先

每个阶段、月和周都应围绕一个可解释的 C 端 AI 产品任务组织，而不是只围绕课程章节组织。完整任务至少应包含：用户问题、目标用户、使用场景、产品假设、AI 介入点、体验路径、评估方式和输出证据。

主线项目可以围绕 `codex-study-os` / AI 学习成长 Agent 展开，但训练过程不能只围绕一个 Agent。系统应定期引入短小的 C 端 AI 产品实战题，可结合热点、时事、真实产品案例、资源库案例或常见消费场景，用于训练产品敏感度、迁移能力和判断灵活性。

小实战题不要求每次都形成完整产品闭环。它可以是一次用户问题判断、一个 AI 适用性判断、一个访谈提纲、一个指标设计、一个 onboarding 流程、一个 RAG 方案取舍、一个 eval rubric 或一个失败兜底设计。

每个小实战题必须明确对应训练能力、主线任务或证据缺口，避免碎片化。小题服务完整任务，而不是替代完整任务。

小实战题池的主选来源包括：

- AI 学习 / 个人成长 / 求职成长。
- AI 个人效率 / Workflow / Agent。
- AI 搜索 / 知识消费。
- 热点产品 / 时事案例 / 新 AI 产品案例。

辅助来源包括：

- AI 陪伴 / 社交 / 娱乐互动。
- 长沙本地或目标公司相关 AI 机会。
- B 端 / 企业级 AI / RAG / Agent 备选线。

AIGC / 内容创作 / 创作者工具暂不作为主要题源，除非后续阶段复盘后重新纳入。

## 3. 局部专项补强

当完整任务暴露出局部能力缺口时，再插入短小专项练习。专项练习必须回到原任务中验证，不能变成孤立课程。

专项练习可覆盖用户访谈、JTBD、指标设计、RAG、Agent、eval、Demo 技术学习或求职表达，但都应服务于当前产品任务。

专项练习可以短暂集中，例如连续几天练习访谈问题改写、指标设计、RAG 检索实验或 eval rubric 设计；集中练习结束后必须回到完整任务，检验该能力是否能迁移使用。

## 4. 脚手架递减

前期提供较强脚手架，包括示例、模板、问题清单、反例和检查表；中期减少提示，要求用户做更多独立判断；后期转为用户先产出，AI 主要做 reviewer、追问者和风险检查者。

脚手架必须服务完整产品任务，不能把学习变成机械填表。每次使用脚手架后，下级计划或备课文件应考虑是否需要降低下一轮脚手架强度。

## 5. 检索练习与间隔复习

恢复旧知识时，先让用户回忆、解释和应用，再查阅笔记、书籍或课程。复习不以重复阅读为主，而以“回忆 -> 应用 -> 查漏 -> 修正”为主。

Phase 0 应采用快速回顾和应用练习结合的方式：先快速回顾旧模块，再用小型 C 端 AI 产品场景进行检索练习和应用；发现断点后，再局部回补具体资源。

关键概念应在后续阶段中间隔重现，例如用户访谈、JTBD、指标、RAG、Agent、eval 和作品集表达都应在不同任务中多次出现，而不是只在某一阶段一次性学完。

## 6. 螺旋递进

核心概念应在不同复杂度的任务中反复出现。早期以低保真问题判断和简单练习为主，中期加入体验、指标、AI 实验和 eval，后期进入 Demo、反馈、迭代和求职表达。

螺旋递进不是重复学习同一内容，而是在每次重遇时提高任务复杂度、减少脚手架、增加独立判断要求。

## 7. 交错练习与必要集中练习

在相近但不同的 C 端 AI 场景中反复练习，让用户判断何时使用用户访谈、JTBD、指标、RAG、Agent、eval、Demo 或求职表达等工具。交错练习的目标不是增加任务数量，而是训练迁移和判断。

当用户第一次学习某个局部能力，或在任务中暴露明显短板时，可以短暂采用集中练习；当基本概念建立后，应回到交错练习和完整任务应用。

## 8. 形成性评价

每个关键产出都要有检查标准，用于发现缺口和决定下一步补强。`master_plan.md` 只规定关键产出必须有检查标准；具体检查清单由 stage、month、week 或 lesson prep 文件生成。

评价不是为了给学习者打最终分，而是为了调整学习路径、资源调用和脚手架强度。

复盘应检查 4C/ID 四类要素是否有效：完整任务是否清晰，课程支撑是否服务任务，程序性脚手架是否过强或不足，局部专项练习是否解决真实短板。小实战题还应检查是否促进迁移和产品敏感度，而不是变成碎片任务。

## 9. 目标、任务、资源、证据对齐

每个阶段和下级计划都应保持目标、任务、资源和证据对齐。资源选择必须服务当前能力缺口和产出证据，不能因为资源热门就加入计划。

具体 Resource ID 应在 `annual_plan.md`、`current_stage.md`、`current_month_plan.md` 或 `current_week_plan.md` 中，根据阶段目标、资源复核结果和 `current_status.md` 逐级选择。

下级计划生成时，应回答四个问题：

1. 当前完整任务是什么？
2. 需要哪些课程、书籍、官方文档或案例作为支撑？
3. 需要哪些模板、步骤、检查表、反例或质量标准作为脚手架？
4. 当前任务暴露了哪些短板，需要什么局部专项练习？

## 10. 认知负荷控制

每个学习周期只引入有限的新概念。月计划、周计划和日计划必须控制任务复杂度，不把产品、AI、代码、eval、用户研究和求职表达一次性压入单日任务。

如果某个任务同时要求过多新能力，下级计划应拆分任务、增加脚手架，或将部分内容延后。

## 11. 计划与备课分离

计划回答“做什么”，备课回答“如何学、如何练、如何检查”。后续下级文件应支持：月计划 -> 月度备课 -> 周计划 -> 周度备课 -> 日计划 -> 日度备课 -> 执行 -> 复盘 -> 更新 `current_status.md` 的路线。

月度备课文件从 `current_month_plan.md` 派生，负责说明本月如何学、如何练、如何检查，以及需要哪些脚手架。周度备课文件从 `current_week_plan.md` 派生，负责说明本周的讲解路径、练习设计、反例、检查标准和局部专项练习。日度备课文件从 `daily_plan` 派生，负责说明当天如何执行学习任务、使用哪些材料、完成什么练习、如何判断完成质量。

备课文件不替代计划文件，不记录完成事实，不直接更新 `current_status.md`。下级计划和备课文件生成时，应尽量保持 4C/ID 四类信息清晰：完整任务、支撑资源、程序性脚手架和局部专项练习。

本文件只定义备课原则，不创建月度、周度或日度备课模板。具体模板应在后续 lesson prep 相关文件中建立，并且不得破坏现有计划层级。

## 12. 自我调节与复盘

学习者需要定期记录：我理解了什么、哪里卡住、哪个方法无效、下一步需要什么脚手架。复盘优先更新 `current_status.md`，不直接改写 `master_plan.md`。

## 13. Phase 1-5 学习方法论安排

Phase 0 已承担恢复性复习和旧知识检索，不再额外叠加新的学习方法论主题。Phase 1-5 应每个阶段安排少量学习方法论输入和应用练习，原则是“学一个方法，用到当前 AI PM 训练中，并在复盘中判断是否保留”。

学习方法论不是独立读书线，也不是额外课程完成目标。它必须服务当前阶段的完整任务、学习节奏、作品集证据或求职表达。

| Phase | 学习方法论主题 | 应用方式 | 证据 |
| --- | --- | --- | --- |
| Phase 1 | 习惯设计与最小行动 | 用身份型习惯、环境提示、固定触发器和最小行动恢复稳定学习节奏 | 阶段学习习惯设计说明 |
| Phase 2 | 刻意练习与反馈循环 | 选择一个用户研究、指标或体验判断短板，设计短练习、获得反馈并修正 | 关键能力刻意练习记录 |
| Phase 3 | 复杂概念学习与费曼解释 | 用自己的话解释 LLM / RAG / Agent / eval 概念，并说明产品适用边界 | 技术概念解释记录 |
| Phase 4 | 项目制学习与范围控制 | 用范围收敛、能量管理和阶段性复盘推动作品集项目形成可展示证据 | 项目推进复盘 |
| Phase 5 | 反思性实践与知识外化 | 把学习过程、项目取舍和能力变化转化为作品集叙事、面试故事和个人学习原则 | 个人学习方法复盘 |

下级计划安排学习方法论时，应遵守：

- 每阶段只选少量方法，不堆砌学习技巧。
- 方法必须绑定当前阶段任务，不做脱离 AI PM 转型的独立阅读任务。
- 可以复用用户过去学过的原子习惯等方法，但必须转化为本阶段可执行规则。
- 复盘时判断方法是否真的降低阻力、提升质量或增强迁移，不把“知道方法”当成完成。
- 如果学习方法论与主任务冲突，应压缩方法论输入，优先保证主任务证据。
