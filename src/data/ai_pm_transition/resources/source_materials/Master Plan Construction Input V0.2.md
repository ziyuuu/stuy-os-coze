# 6. 战略定位：一主线，一备选，一系统

## 6.1 主观目标主线

```text
C 端 AI Product Manager / AI-native Consumer Product Manager
```

重点关注：

* AI 学习 / 个人成长产品；
* AI 求职 / 职业规划 / 复盘产品；
* AI 个人效率 / Workflow / Agent；

* AI 陪伴 / 社交 / 娱乐互动作为观察方向。

---

## 6.2 现实备选线

```text
企业级 AI / 政企数据平台 / 数据与知识平台 / B 端 Agent
```

保留原因：

* 与既有背景复用度高；
* 与长沙机会更匹配；
* 与 RAG、Agent、Workflow、eval 等能力有共用底座；
* 可以作为求职风险对冲。

有效岗位研究也显示，企业级 AI 平台 PM、政企数据平台 PM、知识/RAG 和 B 端 SaaS/ERP + AI 是用户背景更容易迁移的方向。

# 10. 资源策略

## 10.1 资源总原则

正式 Master Plan 中应写入：

```text
能力缺口 → 练习任务 → 作品集证据 → 资源选择
```

而不是：

```text
热门课程 → 学习安排 → 假设能力提升
```

---

## 10.2 稳定资源与高时效资源区分

| 资源类型                 | 策略            |
| -------------------- | ------------- |
| 产品经典书                | 可稳定使用，用于复习和夯实 |
| 用户研究 / C 端产品方法       | 可用经典材料 + 近期案例 |
| AI PM 课程             | 需筛选更新日期和实战性   |
| LLM / RAG / Agent 文档 | 必须优先官方和近期资料   |
| eval / observability | 必须查最新实践       |
| 训练营广告                | 不作为主资源        |
| 无作者路线图               | 不采信           |
| 盗版材料                 | 禁止            |

---

## 10.3 资源复核机制

Master Plan 应写入：

* 产品基础资源：半年复核一次即可；
* AI 技术资源：每 1–3 个月复核一次；
* 岗位 JD：每季度复核一次；
* 作品集相关工具：项目阶段开始前复核；
* 资源进入主计划前，应检查：

  * 日期；
  * 作者 / 机构；
  * 是否官方；
  * 是否有案例；
  * 是否能导向练习；
  * 是否服务目标岗位；
  * 是否存在版权或隐私风险。

# 11. 教学材料与用户数据边界

必须写入 Master Plan 边界规则。

## 11.1 教学材料

可以研究、引用、学习：

* 官方文档；
* 书籍；
* 课程；
* 博客；
* 案例；
* 开源项目；
* 合法公开资料。

但不得：

* 复制全文；
* 使用盗版；
* 未授权聚合；
* 把付费课程内容喂给系统；
* 把未经授权材料做成公开知识库。

---

## 11.2 用户学习数据

不得随意收集：

* 学习行为；
* 测评结果；
* 作业；
* 简历；
* 对话记录；
* 学习计划；
* 个人目标；
* 反馈记录中的可识别信息。

如果未来做用户访谈 / 测试，必须：

1. 明确告知目的；
2. 获得同意；
3. 最小化收集；
4. 匿名化记录；
5. 允许撤回；
6. 不展示可识别内容；
7. 作品集中只展示聚合或脱敏结果。

这一点来自教学材料研究的明确结论：用户学习数据不可随意使用，需授权、匿名化和最小化处理。
