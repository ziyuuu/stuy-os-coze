- **丰富的资源池**：本报告覆盖产品管理基础（产品发现、访谈、MVP、Roadmap、AARRR 等）、C 端产品（用户研究、UX、增长、留存、激活、A/B 测试等）、AI 专项（LLM、Prompt、RAG、Embedding、Agent、AI UX、AI 安全合规、反馈循环等）、AI 原型（AI 辅助原型、vibe coding、前端后端工具）、作品集与求职表达等模块。资源类型包括官方文档、学术课程、经典书籍摘要、高质量行业文章、真实产品案例、开源教程等。

# 2. Resource Selection Principles  
- **能力缺口导向**：从用户的“能力缺口”出发，先确定需要补充的知识和技能，再设计练习项目，最后通过作品集或案例验证学习成果，最后选择匹配这些目标的资源。换言之，“目标→练习→成果→资源”顺序。  
- **稳定资源 vs 高时效资源**：基础理论和管理流程类资料（如经典书籍、成熟框架、行业报告）稳定适用，可定期（半年或年）复核更新；新兴技术类资料（LLM 模型、RAG 策略、Prompt 方法、Agent 工具等）需要季度或月度关注最新进展。优先使用有版本或日期标记的文档，例如 OpenAI、Google、LangChain 等官方指导。  
- **课程非练习替代**：课程、教程提供体系化指导，但不能替代实际练习。选择资源时应考虑是否包含实操项目或练习任务（如 Coursera 课中的动手练习、LangChain 教程的代码demo 等）。练习价值高的资源更可产出可展示的证据。  
- **官方文档优先**：官方文档通常最新且权威，尤其是技术实现部分。例如 OpenAI 的提示工程指南【58†L31-L39】、OpenAI 检索 API 文档【15†L668-L677】、Microsoft/Google 的 AI 安全合规手册，LangChain、Pinecone 等库的教程，都应优先参考。  
- **严禁盗版和侵权**：资源严格限于合法渠道，不使用盗版课程、电子书和未经授权的聚合内容。引述时只摘录必要核心观点，避免整段复制。  
- **数据合规和隐私**：设计学习方案时不收集真实敏感数据。用户研究或测试必须授权且最小化原则，结果匿名化。  
- **复核与迭代**：任何资源入选后都应记录复核日志并定期验证（例如：AI 技术文档需月度、C 端案例半年复核）。资源质量评估以权威性、实用性、更新频率和与目标贴合度为标准。

# 7. Course / Book / Official Doc Quality Evaluation  
- **AI PM 课程**：评估讲师资质（来自大厂或权威机构）、课程内容更新（是否涵盖最新模型/框架），学员评价和项目实践。好的课程应包含实际项目（如 AI 产品策划、角色扮演、Prompt 调优练习），而不仅是理论。Check 课程大纲是否覆盖本报告需求（Prompt、RAG、Agent 等），以及是否提供评估反馈和社区支持。  
- **C 端产品课程**：评估是否关注用户研究和可用性（课程中是否有用户访谈、原型设计、可用性测试案例）。权威性可以参考讲师背景（大厂产品经理或NN/g导师）。检视课程更新时间，过于陈旧的案例需要谨慎。课程最好带实践环节，如 UX 设计小项目或增长策略练习。  
- **产品书籍**：判定是否值得读的标准包括：出版年份、作者影响力、行业认可度（如《启示录》《精益创业》等经典常读；新书需看作者或背景公司权威）。关注书中案例是否贴近当前趋势（例如5年前的增长书籍在 AI 时代可能要批判性对待）。如果书已出新版或新补充材料优先阅读最新版。  
- **RAG/Agent 教程**：应注意出版/更新日期和兼容性。早期教程可能针对旧版库或模型，不一定适用。优先使用官方或社区活跃作者的教程（如 LangChain、OpenAI 示例），并查看 GitHub 提问数和最近提交时间以判断维护情况。检查教程是否有完整的实例代码和数据，以及是否说明模型版本和参数。  
- **AI 编码/原型教程**：评估是否覆盖现代前端后端技术栈（如 Next.js, React, Supabase, Vercel 等）。查看是否使用最新框架版本，演示项目是否能在本地或云端一键运行。好的教程应包含完整代码、部署指导和注释，并注明许可协议。避免只讲概念不演示的教程。  
- **AI 产品案例**：判断是否学习材料要看案例来源（是否官方博客或权威媒体）、案例深度（是否揭示产品设计逻辑及挑战）。官方博客（如 Duolingo、Notion）或行业一线媒体案例更可信。应关注案例具体细节：功能交互、用户定位、商业模式、技术实现等，并非简单功能介绍。对比多个案例学习其共性和差异。  

# 8. Not Recommended / Caution List  
- **过时教程**：使用仅针对旧版 LLM 或已弃用库（如老版 RAG 工具或已被新版取代的教程）。  
- **空洞工具清单**：只列举工具名称却无具体方法论或实践指导的文章。  
- **训练营广告**：没有实质内容、过度营销的速成班或研讨会宣传页。  
- **无凭无据的路线图**：没有作者、没有日期、无背景说明的“AI PM 路线图”、“产品经理转型图表”等。  
- **盗版/侵权资源**：盗版课程、盗版电子书、未经授权的资料聚合网站。  
- **黑盒教条**：强调“教你不需要编码”“随便搞定 AI”之类夸大宣传而缺乏实操的速成课程。  
- **非目标定位**：专门针对 B2B 领域的资源（如深度大数据平台）如果与 C 端 AI 产品目标不符，应谨慎。  
- **过度营销案例**：公司白皮书或产品广告而缺乏客观分析的内容。  

# 9. Resource Freshness and Review Mechanism  
- **产品基础资源**：如经典书籍、敏捷实践文档，可半年至一年复核一次，检查是否仍适用当前环境（组织或行业变化）。  
- **C 端产品案例**：市场和用户需求变化快，可建议每季度或半年复核一次，关注最新成功案例或失败教训。  
- **AI 技术文档**：AI 模型和技术更新极快（几个月出新模型），建议月度或季度复核，如 OpenAI 文档、LangChain 发布新版本。  
- **AI 编码/Demo 工具**：前端后端框架和 AI 工具迭代频繁（React 新版、Supabase API 变动等），建议月度追踪更新。每次使用前先查版本兼容性。  
- **JD/岗位要求**：岗位需求更新缓慢，可半年监控一次，比如随大厂招聘动态或招聘网站职位要求更新。  
- **资源状态转换**：资源初选为 “candidate”，在审核与实践后可升级为“active resource”；发现问题或过时则降级为“defer”或“exclude”。重要资源在实际教学中验证效果后，可标记为“previously_used”。  

# 10. Copyright and Data Boundary  
- **教学材料使用**：课程、书籍、博客、官方文档等内容仅可引用观点和事实，不得整段复制并喂给模型。引用需保留出处格式（见表格要求）。  
- **不同形式引用**：  
  - *课程*：引用课程大纲或视频描述时注明来源。直接课程视频或课件不可公开转载，仅能转述要点。  
  - *书籍*：遵守版权法，只提炼关键观点并引用书中可许可摘录部分（如开头、结论或关键示例的一两句）。  
  - *博客/文章*：可以完整引用短段文字（如权威博客一句话定义），同时附上明确来源。  
  - *官方文档*：通常可自由引用文档内容，但仍需注明文档标题和链接。  
  - *开源项目教程*：使用时注明项目名和链接。开源代码可用作 Demo，但需注意开源协议许可（MIT、Apache 等）。  
- **用户学习数据**：不允许未经用户同意擅自收集学习行为数据。可用匿名化统计（如页面访问次数）做改进参考，但避免关联个人身份。  
- **用户访谈/测试**：必须取得被访者同意，并说明用途。采集最少必要信息（最小化原则），敏感个人信息进行匿名化处理。用户反馈引用时去除姓名等标识。  
- **作品集展示**：在作品集或案例中引用资源时，注明来源。例如：引用用户访谈片段时保留匿名性，只注明“基于用户反馈”。展示第三方工具或内容（如API图表、UI素材）时，需说明其出处或许可（例如“使用了OpenAI API，数据来源xxx”）。
