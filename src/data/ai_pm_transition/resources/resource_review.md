# 资源复核

本文件承接 `master_plan.md` 中的资源复核机制细则，用于判断候选资源是否可以进入年度、阶段、月、周或日计划。

本文件不是具体资源复核记录，不生成资源质量结论，不创建学习资源清单。逐次复核记录应在后续单独资源复核任务中创建或写入获批准的复核记录文件。

## 1. 复核原则

资源状态只能在复核后转换，不得因为被列入 `resource_catalog.md` 就自动成为已批准学习任务。

`resource_catalog.md` 中有三个容易混淆的字段：

- `Status`：候选资源当前状态，描述资源在候选池中的处理阶段。
- `Freshness`：资源新鲜度或复核频率，描述后续需要多久检查一次。
- `Recommendation`：复核建议，描述该资源是否可进入候选池、辅助使用、暂缓或排除。

资源进入下级计划前，应检查：

- 日期和版本。
- 作者 / 机构。
- 是否官方或可信。
- 是否有真实案例。
- 是否能导向练习。
- 是否服务目标岗位。
- 是否能形成作品集证据。
- 是否存在版权、隐私或数据风险。
- URL 是否有效。
- 是否官方或维护活跃。
- 是否服务当前 Phase 的能力缺口。
- 是否需要付费，以及费用是否值得。

## 2. 复核节奏

- 产品基础资源：半年或年度复核。经典书籍、成熟产品框架和用户自有笔记相对稳定，但要结合实际练习验证是否仍适用。
- C 端产品案例：季度或半年复核。关注 AI 学习、个人成长、效率、知识消费、用户信任、Onboarding、增长和商业化的新案例。
- AI 技术文档：月度或季度复核。OpenAI、Anthropic、Google、LangChain、LlamaIndex、向量数据库和 eval 资源更新快，使用前必须确认版本。
- AI coding / Demo 工具：使用前复核。Cursor、Codex、Next.js、Vercel、Supabase、Firebase、开源示例和框架依赖变化快。
- JD / 岗位要求：季度或半年复核。用于校准 C 端 AI PM 主线、远程机会和长沙本地 B 端 / 企业级 AI 备选线。
- 作品集相关工具：项目阶段开始前复核。

## 3. 候选状态枚举

`Status` 字段只使用以下值：

- `previously_used`：用户已学习、使用或拥有的历史资源；仍需在进入新计划前判断是否适配当前任务。
- `candidate`：普通候选资源；可保留在候选池，使用前仍需复核。
- `high_priority_candidate`：高优先级候选资源；更可能服务近期能力缺口或作品集证据，但仍不是已批准学习任务。
- `review_required`：信息不完整、版本不明、费用不明、来源需补全或质量需确认；使用前必须复核。
- `auxiliary`：辅助参考资源；可用于补充视角，不作为主学习路径。
- `not_recommended`：不推荐资源；原则上不得进入学习计划。
- `defer`：暂缓资源；除非阶段目标或备选线需要，否则不进入近期计划。

`Status` 不等于已批准。即使状态为 `previously_used` 或 `high_priority_candidate`，也必须结合阶段目标、版权边界、时间投入和当前状态进行二次复核。

## 4. 新鲜度枚举

`Freshness` 字段只使用以下值：

- `stable`：相对稳定资源，例如经典书籍、成熟产品框架或用户自有历史资产。
- `quarterly_review`：建议季度复核，适用于 C 端案例、岗位资料、产品案例、部分工具文档和观点型资源。
- `monthly_review`：建议月度复核，适用于 LLM、RAG、Agent、eval、AI coding 和高变化官方文档。
- `high_risk_outdated`：高过时风险资源；只能辅助观察或作为反例，使用前必须用更新资料校验。

## 5. 不得进入学习计划或主学习路径

以下资源可以作为排除清单或谨慎清单被记录在 `resource_catalog.md` 中，但不得进入已批准资源、学习计划或主学习路径：

- 盗版或未授权资料。
- 未经复核的训练营或营销课程。
- 无作者、无出处、无案例的路线图。
- 过时且无法复现的 AI 工具教程。
- 只列工具名、不提供方法或练习的工具清单。
- 盗版课程 / 盗版电子书 / 未授权聚合资料。
- “不用理解技术也能搞定 AI PM”的黑盒教条。

## 6. 复核输出

资源复核结论至少应区分：

- `include_in_catalog`：可进入候选池，但仍不是必学任务。
- `include_as_auxiliary`：可作为辅助参考，不能作为主学习路径。
- `review_before_use`：保留候选资格，使用前必须再次复核。
- `defer`：暂缓使用，除非阶段目标发生变化。
- `exclude`：不得使用。

复核记录应说明：

- 资源名称、URL / 来源、作者 / 机构和更新时间。
- 适用能力模块、适用 Phase 和使用方式。
- 预期练习产出和作品集证据。
- 版权、隐私、数据、安全或过时风险。
- 是否需要付费。
- 本次结论和下次复核时间。

## 7. 与下级计划的关系

复核结果可影响 `annual_plan.md`、`current_stage.md`、`current_month_plan.md`、`current_week_plan.md` 或 `daily_plan` 的资源选择，但不直接重写 `master_plan.md` 的总目标。

未经复核的资源不得从候选池直接变成必学任务。下级计划绑定具体 Resource ID 时，必须结合阶段目标、资源复核结果和 `current_status.md` 当前状态逐级选择。

## 8. 边界说明

- 当前不评价任何具体资源。
- 当前不生成资源质量结论。
- 当前不创建学习资源清单。
- 当前不新增具体课程清单。
- 当前不绑定具体 Resource ID 到学习计划。
