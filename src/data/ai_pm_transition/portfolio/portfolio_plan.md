# 作品集计划

本文件承接 `master_plan.md` 中的作品集策略和展示边界细则，用于后续规划 AI PM 转型作品集证据链。

本文件不是项目记录，不代表作品集项目已最终确定，不记录作品集进度。真实作品集方向必须在 Phase 0 / Phase 1 复盘后，通过单独用户批准任务规划。

## 1. 作品集目标

12 个月内形成：

- 1 个主作品集项目。
- 1 个轻量备选 demo / case。

作品集必须证明 AI PM 的闭环能力，而不是只展示 PRD、截图或 AI 效果。

核心证据链应覆盖：

- 问题定义。
- 目标用户与场景。
- 产品机会判断。
- PRD。
- 原型。
- Demo。
- AI 架构或 Agent / RAG / Workflow 设计。
- eval。
- 测试集 / rubric。
- 轻量用户反馈。
- 迭代记录。
- Demo 讲述稿 / Portfolio 页面。

## 2. 主项目候选

主项目候选是 `codex-study-os` / AI 学习成长 Agent。

当前定位：

- 本地文件系统 + Codex 辅助运行的个人学习操作系统雏形。
- `ai_pm_transition/` 的学习承载工作区。
- 未来可能演化为 AI 学习 / 个人成长 / 求职成长 Agent 的长期项目候选。

不得把它写成已完成 AI Agent。

如果后续选择它作为主项目，必须逐步从自用系统走向可展示产品证据：

- 明确目标用户，不只服务个人自用。
- 明确用户问题，不只展示文件结构。
- 形成 C 端体验和 Onboarding。
- 有可运行 Demo。
- 有 eval、测试集和 rubric。
- 有 3-5 个轻量用户反馈或 Demo 测试。
- 有版本迭代记录。
- 有可面试讲述的产品故事。

## 3. 辅助项目候选

轻量备选 demo / case 可以从以下方向中选择：

- AI 搜索 / 知识消费 / RAG Demo。
- 企业级知识库 / RAG Demo。
- B 端业务流程 Agent / Workflow case。
- 数据与知识平台的轻量产品方案。

辅助项目的作用：

- 补充 RAG、知识材料处理、引用和来源意识。
- 补充 eval 和测试集能力。
- 支撑 C 端 AI 搜索 / 知识消费方向。
- 为企业级 AI / B 端 AI 备选线保留证据。

## 4. 决策规则

作品集项目方向不得在 `master_plan.md` 或本文件中写成最终确定。后续应根据 Phase 0 和 Phase 1 的复盘结果，用以下规则选择：

- 是否服务 C 端 AI PM 主线。
- 是否能复用用户既有背景形成差异化。
- 是否能在 12 个月内形成完整证据链。
- 是否能通过低代码或 vibe coding 做出可运行 Demo。
- 是否能设计可执行 eval。
- 是否能安全、合法地收集少量反馈。
- 是否不依赖真实敏感数据或未经授权教学材料。

Phase 0 结束后，应根据复盘结果校准作品集方向。若 `codex-study-os` 无法从自用系统走向可展示产品证据，应保留为学习承载系统，并选择更适合作品集的主项目。

## 5. 评价原则

作品集评价不以“做了多少功能”为核心，而以证据闭环为核心：

- 问题是否真实、清晰、可验证。
- 目标用户和场景是否明确。
- AI 是否真正服务用户任务，而不是为了使用 AI 而使用 AI。
- Demo 是否能证明核心价值假设。
- eval 是否能发现 AI 输出问题。
- 反馈是否授权、匿名化、最小化。
- 迭代是否基于证据，而不是主观补功能。
- 求职表达是否能说明取舍、风险和下一步。

## 6. 展示边界

作品集中可以展示产品判断、设计过程、匿名化用户反馈、聚合测试结果、eval 样例、失败样例分类和迭代记录。

作品集中不得展示：

- 用户可识别信息。
- 完整私人对话。
- 未经授权的简历。
- 未经授权的学习记录。
- 未经授权的职业目标。
- 未经授权的作业内容。

如果需要展示访谈或测试结果，应优先使用摘要、编号化样例、聚合统计和脱敏引用。

作品集展示应区分：

- 用户真实反馈。
- 脱敏样例。
- 模拟测试样例。
- AI 生成样例。
- 作者自己的分析判断。

不得把模拟样例伪装成真实用户反馈，也不得把 AI 生成内容伪装成用户原话。

Phase 0 不安排正式用户访谈。Phase 1 可准备访谈提纲和目标用户假设。Phase 2 可设计用户画像和轻量验证方案。Phase 3 / Phase 4 可寻找 3-5 个目标用户或熟人做轻量访谈 / Demo 测试。Phase 5 再匿名化整理反馈进入作品集。
