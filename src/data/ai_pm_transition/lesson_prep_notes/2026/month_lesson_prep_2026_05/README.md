## 3. 知识地图

### 涉及知识域

- 产品发现与机会判断。
- 非诱导式用户问题探索。
- 问题空间、方案空间、MVP、PMF 和验证路径。
- 现代产品管理基础、产品经理角色、产品焦点和机会取舍。
- 敏捷与设计思维、persona、problem scenario、user story、AC 和 prototype 表达。
- 旧资产审计、能力缺口识别和证据边界。
- C 端 AI idea 发散、AI / 非 AI 方案初判和候选问题筛选。
- 一页纸问题简报和完整产品流程适配性检查。

### 核心概念

| 概念 | 工作定义 | 本月用途 |
| --- | --- | --- |
| 可调用知识 | 能在新问题中被回忆、解释和应用的旧知识 | 判断 49 天旧学习是否能服务当前 C 端 AI PM 训练 |
| 产品发现 | 从机会、用户问题、价值主张和验证路径出发的判断过程 | 支撑 idea 初筛和候选问题判断 |
| 非诱导式访谈原则 | 通过过去行为、具体事实和真实约束判断问题，而不是验证自己的想法 | 用于设计后续验证路径，但本月不启动正式访谈 |
| 问题空间 / 方案空间 | 先确认用户问题、场景和替代方案，再讨论产品方案 | 防止 idea 直接跳到功能或技术 |
| MVP 范围 | 用最小可验证方式检查关键假设的范围 | 判断候选问题是否可控，避免复杂 Demo |
| 旧资产审计 | 判断历史材料是可继承、需重练、仅归档还是暂不使用 | 形成旧资产与能力缺口清单 |
| C 端 AI idea 卡 | 对用户、场景、问题、替代方案、AI 介入点和范围做轻量描述 | 产出 8 个低复杂度 idea |
| 完整产品流程适配性 | 候选问题能否继续拆成 brief、PRD、Backlog、用户故事 / AC、指标和验证路径 | 筛出 2 个 Phase 1 候选问题 |
| 一页纸问题简报 | 用目标用户、痛点、现状、价值主张和待验证假设描述问题 | 为 1 个候选问题生成 Phase 1 输入草案 |

### 概念关系

```text
旧书课/旧笔记/旧产出
-> 检索恢复
-> 旧资产审计
-> C 端 AI idea 发散
-> 2 个候选问题筛选
-> 1 份问题简报草案
-> Phase 1 选择输入
```

### 先后依赖

- 先恢复基础概念，再判断旧资产；否则旧资产审计会变成资料整理，缺少判断标准。
- 先区分问题和方案，再发散 AI idea；否则容易产出工具点、功能点或技术点。
- 先形成 idea 卡和筛选标准，再做候选问题完整流程检查；否则候选问题会过早被写成正式项目方向。
- 一页纸问题简报依赖候选问题筛选结果，但不等于 Phase 1 最终选题。

## 5. 教学顺序

- 步骤 1：先建立“回忆 -> 应用 -> 查漏 -> 修正”的旧知识检索方法，恢复产品基础可调用性。
- 步骤 2：用恢复出来的判断标准审计旧资产，区分可继承材料和能力缺口。
- 步骤 3：在低复杂度 C 端 AI 场景中做 idea 发散，强制写出用户、场景、问题、替代方案、AI 介入点和非 AI 对照。
- 步骤 4：筛选 2 个候选问题，做完整产品流程检查。
- 步骤 5：只为 1 个候选问题写一页纸问题简报草案，作为 Phase 1 输入，不提前定题。

  - 不把课程完成量、阅读量或旧产出存在本身写成能力。

## 7. 检查问题

- 理解检查：
  - 你能否不用看笔记说明产品发现、用户问题、MVP、用户故事和指标之间的关系？
  - 你能否说明为什么本月不应该直接启动复杂 Demo 或正式访谈？
  - 你能否说清“候选问题”和“已选主项目”的差别？
- 产出检查：
  - 复习摘要是否能连接到 C 端 AI 产品练习？
  - 旧资产清单是否有处理结论，而不是只列目录？
  - 8 个 idea 是否都包含用户问题和 AI / 非 AI 初判？
  - 2 个候选问题是否都能承接 brief、PRD、Backlog、用户故事 / AC、指标和验证路径？
- 边界检查：
  - 是否把计划内容写成完成事实？
  - 是否把资源学习量写成目标？
  - 是否把旧产出写成当前作品集证据？
  - 是否新增了月计划未确认的目标、模块或产出？
